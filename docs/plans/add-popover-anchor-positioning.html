Context

The repo already ships a native-popover component (plugins/acss-kit/skills/component-popover/) built on the exact HTML Popover API in the reference links — popover attribute + popovertarget + showPopover()/hidePopover(), auto/manual modes, light-dismiss, top-layer. So this is an enhancement, not a new build.

Reviewing it against the goal ("reusable for dropdown nav and tooltips") surfaced four real gaps: (1) no real positioning — the component fakes placement with a data-placement arrow but never tethers the popover, so an auto popover lands in the viewport's top-layer center, broken for a dropdown or tooltip; (2) no role semantics — the reference explicitly punts role to the consumer; (3) no hover/focus open for tooltips — native popovertarget is click-toggle only; (4) the arrow doesn't track flips when position-try repositions the popover.

Hard constraint — dual-source parity. The generator source of truth is the neutral popover.component.md; reference.md is its byte-identical fallback. Every template edit must land in both files. The real enforcement (corrected after review): tests/run.sh step 2a diffs the extracted SCSS of both files against the golden fixture tests/fixtures/golden/component-popover/popover.scss — so SCSS drift is caught automatically, but TSX parity is not (that guard was deferred), so the TSX-touching steps must be diffed by hand. Editing the SCSS also means the golden fixture has to be regenerated, or tests/run.sh goes red.

Browser support (drives the fallback choice): CSS Anchor Positioning ships in Chrome/Edge 125+ and Safari 26+ but not yet Firefox. So anchor positioning is the modern path wrapped in @supports (anchor-name: --a), with a @supports not (...) fallback that keeps the popover usable where anchoring is absent.
